# 支援流改版草案（未实现 · 2026-09）

## 核心卡：压分辅助（玩家主动压低自己的分来放大全队）

| 项目     | 值                             |
| -------- | ------------------------------ |
| 该 Tee   | 得分 +20（同时保证分母不为 0） |
| 骰子映射 | 掷出的 **1、6 视为 4**         |
| 全队     | 分数 ×（邻居分 / 该 Tee 分）   |

设计意图：这是全池**唯一一张让玩家想压低自己输出的卡** —— 支援位变成牺牲位。
它给的是**结构性（乘算）**杠杆，而不是又一个固定倍率。

## 待定（实现前必须钉死）

1. **上限**：`邻居分 / 该Tee分` 必须有 clamp（建议 1~3）。否则自己 20 分、邻居 300 分
   就是全队 ×15，直接爆表。
2. **「邻居分」取谁**：左邻 / 右邻 / 左右平均。
3. **结算顺序**：与接力回流 `relay_pct` 的先后。
   建议：各人分 → 接力回流 → 这个比率 → 全队倍率。
4. **压制怎么玩出来**：玩家会主动用「烂打法」把自己的分压住。模拟器必须允许
   对这张卡的持有者切换成**最小化**策略 —— 现在 `run.ts` 的 `skill='opt'` 是全员
   最大化自己得分，照这样量，这张卡的价值会被系统性低估。

## 诊断：支援流不是「前期散伙」，是「平台期」

`TRACE=支援流 WORKERS=0 TRIALS=2 bun run tools/zhongqiu/run.ts`（2026-09）：

```
 R1  105 / 60       R5 1525 /  750     R9  1857 / 1460
 R2  935 / 180      R6 1573 /  885     R10 3605 / 1725
 R3 1112 / 360      R7 1092 / 1045     R11  960 / 2035  ← 输掉竞速，本局结束
 R4 1314 / 560      R8 1799 / 1235
```

- 目标曲线每关 **×1.43**，而支援流的分长期压在 **1100 ~ 1800** → R7、R11 掉队。
- 卡组抽得没问题：吴刚 / 蜜枣 / 灯谜 / 并蒂莲 / 牵丝戏 / 镜花水月 + 合璧 buff 都上手了。
  **所以病根不是「拿不到卡」，而是没有跟得上目标增速的引擎。**
- 先前「中位结束 R4 = 前期就散了」的解释是错的：中位数低是因为少数局在开局
  抽卡运气差时崩掉，而绝大多数局是在 R7 之后**被目标增速拖死**。

## 已经试过、确认无效的路子（别再走）

| 尝试                                 | 支援流通关率 |
| ------------------------------------ | ------------ |
| 只有接力回流机制（30/45/75%）        | 5%           |
| + 固定底分 60/100/150、普通卡自保+45 | 3%           |
| + 复利引擎（全队倍率每关+3%）        | 4%           |
| 中游流派参照                         | 10 ~ 15%     |

三次都在噪声内（200 局分辨不出 ±3~5%）。结论：**加数值上限（线性或复利）都推不动**，
缺的是让玩家**改变操作方式**的结构性机制 —— 也就是上面那张压分卡。
